# Predictor Budget

**Live tool: https://satsumalab.github.io/predictor-budget/**

How many candidate predictor parameters can a clinical prediction model developed on *your* cohort support?

In retrospective and routinely collected data the sample size is already fixed, so the usual sample-size question runs backwards. This tool takes Riley et al.'s minimum sample size criteria for developing a prediction model (as implemented in the R package [pmsampsize](https://CRAN.R-project.org/package=pmsampsize)) and finds the largest number of candidate parameters whose required sample size still fits your cohort.

It covers **time-to-event (Cox)** and **binary (logistic)** outcomes, and walks you through four steps:

1. **Outcome type**
2. **Your cohort**: patients and events; for survival, also total follow-up and the prediction horizon
3. **Anticipated performance**: pick whatever you have and the tool converts it to an anticipated R²:
   - nothing yet (Riley's conservative default, Nagelkerke R² = 0.15)
   - a previous model's likelihood-ratio χ²
   - a published Nagelkerke or Cox-Snell R², apparent or optimism-corrected
   - a published C statistic (Harrell's C for survival, AUC for binary)
4. **Candidate predictors**: a counter that turns predictors into degrees of freedom (splines, categories, fractional polynomials, interactions)

It then reports the parameter budget across a base case and sensitivity R² values, whether your planned predictors fit, and a criterion-by-criterion breakdown. It also gives code that reproduces the result, with a switch between **R** ([pmsampsize on CRAN](https://CRAN.R-project.org/package=pmsampsize)) and **Python** ([pmsampsize on PyPI](https://pypi.org/project/pmsampsize/), the official port by Whittle and Ensor). Everything runs in the browser and nothing is sent anywhere. The URL can hold a calculation so you can share it.

## Accuracy

`assets/pms.js` is a line-by-line port of pmsampsize 1.1.3 (`pmsampsize_surv`, `pmsampsize_bin` and the Nagelkerke conversion), including its rounding. `tests/` checks it against:

- 685 synthetic input combinations run through the R package (`tests/fixtures.json`, regenerated by `tests/make_fixtures.R`): sample sizes match exactly, error cases included;
- the worked examples in Riley et al. 2019 (Part II): the Harrell's C → R² chain (C 0.69 → D 1.115 → R²_D 0.229 → R²_OQ 0.328 → R²_CS,app 0.052) and the VTE survival example (4286). For the Chagas binary example, criteria 1 and 3 match the paper (623 and 221). For criterion 2 the paper prints 668, while pmsampsize 1.1.3 gives 662. Unrounded prevalences near 0.174 don't reproduce 668 either (0.17 gives 667), so the tool follows the R package;
- the optimism adjustment for a reported R², checked against the equivalent likelihood-ratio route.

The one difference is the binary C statistic → Cox-Snell R² conversion. pmsampsize simulates a million patients with a fixed seed; this tool computes the large-sample limit of that simulation exactly. It matches the simulation's average over ten seeds to within 0.0002. pmsampsize's default seed happens to land about 1.5 Monte Carlo standard deviations low, so R's sample sizes on its `cstatistic=` route can be up to about 2% higher (tested).

```bash
npm test                          # Node 18+; no dependencies
Rscript tests/make_fixtures.R     # regenerate fixtures (needs pmsampsize, jsonlite)
python3 -m http.server            # then open http://localhost:8000
```

### Python users

The generated Python code uses `pmsampsize` from PyPI (`pip install pmsampsize`, Python 3.12+). Version 0.1.0 has one bug: a survival model given a Nagelkerke R² raises `NameError: name 'exp' is not defined`. The generated code patches it in two lines when needed (`pmsampsize.pmsampsize.exp = math.exp`). With that patch, the Python package matches the R package on all 685 test cases. The snippets for getting cohort counts use pandas, and the likelihood-ratio hints cover lifelines (`CoxPHFitter`) and statsmodels (`Logit`).

## Things worth knowing

- **For survival outcomes, the maximum Cox-Snell R² is not uniquely defined, and the package and the paper differ.** The maximum enters the Nagelkerke → Cox-Snell conversion and criterion 2. pmsampsize builds it from an exponential null log-likelihood on events ÷ patients, E ln(E/n) − E, which doesn't depend on time units. Riley et al. 2019's worked example (eq. 13) uses person-time and prints E ln(E/T) + E. On the paper's VTE example the paper gets 0.37 and pmsampsize gets 0.555 (criterion-2 shrinkage 0.73 vs 0.648). We follow pmsampsize so results can be reproduced, but on that example its choice is the more permissive one. To limit the impact, the tool carries a Cox-Snell R² across unchanged whenever the source provides one (a likelihood ratio, a reported Cox-Snell R² or a C statistic), as in the paper's worked examples. Nagelkerke is used only for the 0.15 default and reported Nagelkerke values, where the page flags the result as approximate for survival outcomes.
- **Binary C statistics should be optimism-corrected.** A survival C-index is shrunk for optimism using the previous model's size. A binary AUC is converted as pmsampsize does, with no shrinkage, so it should already be optimism-corrected or from an external validation.
- **Scope.** Time-to-event and binary outcomes only. Competing risks, clustering and missing data are not accounted for. The criteria give a minimum, not a guarantee of a useful model, and the tool does not replace a statistician.

- **Parameters are degrees of freedom of every candidate**, counted before any selection. Univariable screening on the outcome does not reduce the count.
- **For survival outcomes, follow-up time and the horizon don't change the budget.** Only events ÷ patients enters criteria 1 and 2. They feed criterion 3, the precision of overall risk at the horizon, which pmsampsize reports but never uses to raise the sample size. The tool checks that precision on your actual cohort.
- **For binary outcomes criterion 3 sets a floor.** Below about (1.96/0.05)² × prevalence × (1 − prevalence) patients, no model is supported.
- **Nagelkerke vs Cox-Snell carry-over.** pmsampsize rescales a Nagelkerke R² to your cohort's event rate. When the previous study's event rate differs from yours, the two give different answers. The automatic default is described above; you can override it under "More options".
- An R² from a previous model is shrunk for optimism with van Houwelingen's heuristic shrinkage, S = 1 − df/LR, and R²_CS,adj = S × R²_CS,app (Riley et al. 2019, eqs. 3–8).
